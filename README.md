# In Falsus 製卡最佳化

輸入「板子＋粒子庫存」，算出最佳的粒子擺放。不需要安裝任何東西，也不會碰遊戲。

## 開啟
雙擊 **`infalsus_solver.html`**（Chrome / Edge / Firefox 都可以）。資料會自動存在瀏覽器裡。
（舊版介面備份在 `legacy/infalsus_solver_classic.html`，不再更新。）

## 三步驟
第一次打開已經載入**預設配方的板子**和**最新的粒子庫存（五色共 30 種）**，只差填數值：

1. **選配方**：頂端下拉選單選一個配方按「載入」（預設有「找尋夥伴的溫暖目光」「新朋友」）。
   新配方用 **📷 截圖匯入**：選圖、Ctrl+V 貼上，或直接把截圖拖到板子上。
2. **填區域數值**：右側「區域」分頁。在遊戲裡把滑鼠移到區域上會顯示「攻擊力 +x／防禦力 +y」。
   Enter 跳下一格；點板子上的區域也會跳到對應那一列；「快速輸入」可一次貼上多行（每行「攻擊 防禦」）。
3. **按 ▶ 求解**（Ctrl+Enter）。擺放結果直接畫在左邊的大板子上：每顆粒子有編號與外框，區域打 ✓，
   右上角顯示最終攻擊／防禦。

## 畫面說明
- **頂端常駐列**：配方、截圖匯入、粒子上限、最佳化目標、求解、三種目標比較、停止。手機上會有浮動的「▶ 求解」。
- **狀態列**：板子幾格幾區、區域數值填了幾個、粒子幾種幾色；紅／黃色代表還缺東西，點一下跳到對應分頁。
- **板子**：預設「檢視」模式，拖曳平移、滾輪縮放、點區域選取，**不會誤改格子**。要改板子按「編輯板子」
  （塗色、橡皮擦、區域標籤；Ctrl+Z 復原；右鍵或空白鍵拖曳平移）。
- **右側分頁**
  - **區域**：各區域的攻擊／防禦，缺同色粒子的區域會警告。每個區域還有：
    - **🔒 一定要觸發**：勾選後，求解結果「一定」會把這個區域填滿（想拿它的特殊效果時用）。
      可以勾多個；板子上這些區域會標 🔒。如果在粒子數上限與懲罰限制內放不下，結果會顯示「無解」，
      不會硬給一個沒填滿的擺放——這時請取消其中幾個，或放寬「設定」。攻擊／防禦可以留 0，仍然會被填滿。
    - **🛡 免除［乖離／過載／重疊］懲罰 N 點**：特殊效果之一。這個區域填滿後，**那一種**懲罰減去 N（最低到 0）。
      先選種類再填點數（預設乖離）；多個區域的同種免除會加總，不同種類各算各的、不能互相抵銷。
      免除「過載」會讓可以多放的粒子變多（粒子數上限＋可承受的懲罰＋過載免除點數）。
      免除「重疊」要在「設定」分頁開啟「允許重疊」才有用（預設不允許重疊）。填 0 或留空代表沒有這個效果。
      結果的「懲罰」那一列會寫出「🛡免除 過載 −2」，板子上的區域標 🛡載2（乖／載／疊）。
    - **其他特殊效果（備註）**：只是記事用的文字欄，不影響計算。特殊效果**目前都不算進攻防分數**，只有上面兩項（必觸發、免除懲罰）會影響擺放。
  - **粒子**：預設粒子圖塊，點形狀加入／移除，加入後可直接改效能（`133x3, 120x10`＝效能x數量）。
    每個顏色旁的開關決定「這次求解用不用該色」，庫存不會刪。可切換「最新庫存」「較早庫存」、自訂粒子（自己畫形狀）。
  - **結果**：每次求解的記錄，點選任一筆，板子上的擺放就換成那一筆；下面是填滿的區域、平均效能、懲罰、擺放步驟
    （滑鼠移到步驟上，板子上對應的粒子會亮起）。
  - **紀錄**：每次求解完成（「三種目標比較」的每一筆也算）的攻擊／防禦會**自動記下來**，關掉網頁也還在
    （存在這個瀏覽器的 localStorage）。每筆有時間、配方、目標、攻防、基礎值、平均效能、倍率、懲罰、填滿的區域
    （含當時的區域數值）與完整粒子清單；配方名稱可以自己改（板子沒改過才會自動帶入載入的配方名稱），也能寫備註。
    完全相同的擺放只累計「重複次數」，不會重複記。上方有各配方的筆數與最高攻／防小計，**匯出 CSV** 可用 Excel 開啟。
    「匯出全部資料」會連紀錄一起帶走，匯入時依 id 合併；「還原成初始狀態」不會清掉紀錄，只有「清除全部」會。
  - **設定**：旋轉、重疊、懲罰倍率（公式或自訂表）、自訂權重、搜尋時間。
- **三種目標比較**：分別用「平衡／攻擊特化／防禦特化」各算一次，並排比較；每欄最高值用粉紅色標出。
- **⋯ 更多**：配方存檔（含各區域數值）、匯出／匯入資料、載入示範板子、還原成初始狀態。

## 最佳化目標
- 平衡：攻擊＋防禦總和最大。
- 攻擊特化：先求攻擊最大，一樣時才比防禦（防禦特化相反）。
- 自訂權重：目標 = 攻擊×權重 + 防禦×權重。

## 預設資料（`data/`）
這些資料在 `node build.js` 時**內嵌進 `infalsus_solver.html`**，所以網頁一打開就有預設粒子和預設配方。
更新 `data/` 後要重新執行 `node build.js`。

| 檔案 | 內容 |
|---|---|
| `data/particles.json` | **最新的粒子庫存**：五種顏色各 6 種共 30 種，形狀、效能、數量 |
| `data/particles.png` | 上面 30 種形狀的對照圖（編號 R1–P6），用來和遊戲比對 |
| `data/recipe_zhao_xun_huo_ban.json` | 配方「找尋夥伴的溫暖目光」：板子 40 格、7 個區域、粒子數上限 8 |
| `data/recipe_xin_peng_you.json` | 配方「新朋友」：板子 125 格、5 個區域；粒子庫存是較早的版本（只有紅、紫） |

形狀是從遊戲截圖的小圖示轉錄的，請對照 `particles.png` 與遊戲確認；效能填的是每堆的最高值。
粒子庫存會變動（用掉好粒子後最高效能下降、拿到新粒子則上升），形狀不會變；效能與數量要隨庫存更新。

## 目前採用的規則（實測，詳見 `notes_cards_and_crafting.md`）
- 區域內每一格都被**同色**粒子蓋住 → 該區域填滿，加上它的攻／防。
- 最終 = 基礎 × (平均粒子效能/100) × 懲罰倍率；倍率 = 1 − (P/3)²。
- P = 過載（超過粒子數上限）＋重疊＋乖離（互不相連的粒子群數 − 1）；超界不會被選用。
- 粒子**不能旋轉**，形狀方向固定。
- 額外粒子（沒蓋在任何區域上）若效能高於目前平均，可以拉高平均，或用來連接分離的粒子群。
- 「免除懲罰」：每種懲罰各自 max(0, 該種懲罰 − 已填滿區域對該種的免除點數)，三種加起來才是用來查倍率的懲罰；
  懲罰上限（P ≥ 3 無法製作）也是看扣掉免除之後的值。每個區域免除哪一種由你在區域列自己選。
- 「一定要觸發」的區域是硬性條件：求解只在「這些區域都填滿」的擺放裡找最大值（其餘區域照樣可選）。

## 需要你確認的假設
- **異色粒子放在灰格也計入平均效能**：求解器會拿其他顏色的高效能粒子墊高平均。尚未用遊戲驗證；
  想避開就在「粒子」分頁只開啟與區域同色的顏色。
- 乖離是否只看「邊相鄰」：目前是。
- 同形狀的粒子堆疊，求解器假設每顆的效能就是你填的清單（用最高的那幾顆）。

## 開發
```bash
npm run build                # 重新產生 infalsus_solver.html（內嵌求解器、截圖偵測、預設資料）
npm test                     # 先 build，再跑下面三組測試
npm run perf                 # 真實大小題目的效能測試（不在 npm test 裡）
# 也可以單獨跑（不需要 npm）：
node build.js
node test/solver.test.js     # 求解器：公式對照遊戲數值、與暴力解逐題比對、目標與顏色篩選
node test/importer.test.js   # 截圖偵測：三張真實截圖（含縮放到 80%／120%）
node test/presets.test.js    # 內建的預設粒子與預設配方是否完好（要先 node build.js）
```
需要 Node 18 以上，沒有任何套件相依。`infalsus_solver.html` 是**提交進 repo 的成品**（讓人直接下載雙擊就能用），
所以改了 `src/` 或 `data/` 之後要先 `npm run build` 再提交；GitHub Actions（`.github/workflows/test.yml`）會檢查它是不是最新的。
| 想改的 | 位置 |
|---|---|
| 懲罰倍率 | 介面「設定」分頁；程式在 `src/solver.js` 的 `prepare()`（`multArr`） |
| 區域填滿效果（新增效果種類） | 區域資料 `zones[].atk/def`；價值函式在 `scoreExplicit()` 與 `solve()` 的 `currentU()`／`evalCurrent()` |
| 免除懲罰 | `zones[].waive`＋`zones[].wtype`（`disc`／`over`／`overlap`）：`prepare()` 的 `WD/WO/WV`（`WO` 放寬 `maxPieces`）、`solve()` 的 `lbEff()`（剪枝用的有效懲罰下界）與 `evalCurrent()`（實際免除）、`scoreExplicit()`（`waive`／`waiveBy`／`effBy`／`waived`／`Peff`） |
| 一定要觸發的區域 | `zones[].must`：`prepare()` 的 `order`／`mustIdx`、`dfsZone()`（不可略過）、`knap()`（強制選入）、`scoreExplicit()`（`forcedMissing`） |
| 懲罰種類 | `scoreExplicit()`（獨立計分）與 `evalCurrent()`（搜尋中計分）要一起改，測試會檢查兩者一致 |
| 目標（攻擊／防禦特化） | `src/solver.js` 的 `goalWeights()` |
| 截圖辨識（顏色、格距、UI 排除範圍） | `src/importer.js` |
| 版面與互動 | `src/app.template.html` |

## 限制
- 搜尋有時間上限；很大的板子或很多種粒子時可能跑不完，畫面會顯示「時間到：目前最佳」，不保證最優。
- 用額外粒子連接分離粒子群時，最多考慮距離 5 格內的橋接。
- 還沒有處理粒子「特性」與卡牌「特性槽」；區域的「特殊效果」也只能用「一定要觸發」強制填滿，效果本身不計入分數
  （告訴我各效果是什麼，才能把它加進目標函式，例如「觸發某區域有額外加成」）。
- 截圖只能匯入**板子**；粒子庫存的形狀和區域的攻防數值還是要手動（圖示太小且縮放不一致，數值在截圖上也看不到）。
- 截圖匯入：兩個同色區域若剛好相鄰會被合成一個，匯入後請在編輯模式用「區域標籤」分開；被遊戲提示框蓋住的格子偵測不到。

## 聲明
這是玩家自製的非官方輔助工具，與遊戲的開發與發行方無關。`test/fixtures/` 裡的遊戲畫面截圖（只用來測試截圖匯入）
與遊戲內的名稱、圖像，版權屬於原權利人。這個工具只讀你自己貼進去的資料，不會讀取、修改遊戲或存檔。
